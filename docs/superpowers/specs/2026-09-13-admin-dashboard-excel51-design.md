# Sprix Admin Excel 5.1 统一数据链路设计

## 目标

以 `sprixAI数据看板5.1_统一规则版.xlsx` 为业务基线，统一 Dashboard、任务管理中心、平台验收中心和申诉处理中心的演示数据。旧 Mock 中与该基线冲突的数量、金额、分类和结算逻辑不再参与这些模块。

## 唯一控制数

- 统计周期：2026-07-27 至 2026-09-06。
- 任务主记录：10,834 条。
- 发布总名额：18,370 个。
- 执行记录：16,251 条。
- 剩余名额：2,119 个。
- 名额守恒：18,370 = 16,251 + 2,119。
- 累计周验收 GMV：1,699,400 元。
- 六类任务：数据标注、网站开发、营销、设计、知识问答、其他。

## 数据模型

一个任务主记录包含一个或多个名额，一个 `taskId` 可以对应多条 `executionId`。任务主记录和执行记录分别按 Excel 5.1 的分类总量生成，不能继续使用“一条任务等于一条执行”的旧模型。

每条执行记录进入以下一条最终交付路径：

1. Agent 自动提交并直接通过质检，记为“Agent 自动交付”。
2. Agent 结果未直接通过，人工修正、补充并上传后完成验收，记为“人工上传交付”。

质检通过率采用金额口径：

```text
Agent 自动交付金额 / 分类验收 GMV = Excel 周质检通过率
人工上传交付金额 = 分类验收 GMV - Agent 自动交付金额
```

记录数量按质检比例就近取整，金额比例必须精确对账。最后一周“其他”质检通过率保留 39%。

## 日数据与周数据

- 周新增 Agent 拆成 7 天，工作日整体较高，周末显著降低。
- 周交付任务量按任务类型拆到日，日交付任务数不得小于日有效 Agent 数。
- 同一周的日有效 Agent 使用不重复的周内 Agent 池，7 天合计还原周有效 Agent 数。
- 日任务量、金额和交付方式可以波动，但按周、按类型汇总必须还原 Excel 控制数。
- 周验收 GMV 保持周粒度展示；任意日期筛选时纳入相交的完整周。

## 模块关系

### Dashboard

展示新增 Agent、异构占比、周验收 GMV、任务主记录、总名额、执行记录、剩余名额、有效 Agent、单 Agent GMV、六类任务量和金额、质检通过率、Agent 自动交付金额、人工上传交付金额及两类待结算金额。

### 任务管理中心

列表总数使用 10,834 条任务主记录。每条任务显示总名额、剩余名额和执行数量。按当前每页 20 条计算，最新两页共 40 条全部为工业级数据标注任务。手机号只从 40 个脱敏号码循环池中映射。

### 平台验收中心

列表基于 16,251 条执行记录生成，明确区分 `AGENT` 和 `USER_MANUAL`。人工上传记录必须关联原执行记录，不额外增加执行总数。

### 申诉处理中心

申诉只能从需要人工介入的执行记录中产生，同一执行最多一条。申诉数据用于模块演示，不改变任务量、验收 GMV、交付方式比例或待结算金额。

### 待结算

资金管理中心继续隐藏。Dashboard 仅展示：

```text
纯 Agent 待结算 = Agent 自动交付金额 × 10%
人 + Agent 待结算 = 人工上传交付金额 × 60%
```

## 展示原则

沿用当前后台的白色表面、清晰分隔和紧凑表格。Dashboard 增加任务与名额守恒、交付方式金额拆分，不引入渐变、玻璃效果、阴影或装饰性模块。行为数据继续放在独立二级菜单。

## 强校验

- 每周六类任务量之和等于周交付任务量。
- 每周六类验收金额之和等于周验收 GMV。
- 每周、每类自动交付金额与人工上传金额之和等于分类验收金额。
- 每周、每类自动交付金额除以分类验收金额等于 Excel 质检通过率。
- 所有任务的总名额等于执行记录加剩余名额。
- Dashboard、任务、验收和申诉读取同一份确定性生成结果，不各自硬编码。

## 范围边界

- 不修改后端 API、Swagger、身份认证和生产数据。
- 不恢复资金管理中心导航或路由。
- 不重构行为数据分析模块。
- 不覆盖当前工作树中的其他用户改动。
