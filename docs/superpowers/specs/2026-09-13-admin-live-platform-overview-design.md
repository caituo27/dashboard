# 管理后台平台累计规模动态刷新设计

## 目标

让数据概览顶部的平台累计规模每 5 分钟更新一次，同时保持任务主单口径不变。

## 数据规则

- 初始累计成交金额为 `2,286,100` 元。
- 初始累计订单为 `20,795` 笔。
- 累计任务数量固定为 `13,863` 个任务主单。
- 初始 Agent 数量为 `34,519`。
- Mock 服务运行期间每满 5 分钟生成一轮变化。
- 每轮仅为顶部累计订单增加 1–5，并按这些模拟成交增加随机成交金额。
- 不生成订单、执行记录、交付结果或附件，也不关联任务。
- 不修改任务的已执行数量、已完成数量、剩余名额或上下线状态。
- Agent 数量每轮独立随机增加 1–5。
- Mock 服务重启后恢复初始累计值，不写入业务明细或持久化状态。

## 实现边界

Mock 服务维护进程内顶部累计状态，并只在 Dashboard 响应发出前覆盖 `overview`。前端使用现有 React Query 请求，每 5 分钟重新获取一次数据。顶部指标不提供实时订单入口；下方按日和近六周经营数据、订单、任务、验收及其历史快照均保持按周更新。

## 验证边界

按项目规则不运行测试或 Playwright。仅检查新增 Mock 模块的 JavaScript 语法、TypeScript 改动和最终 diff。
