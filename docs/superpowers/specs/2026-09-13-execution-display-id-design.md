# Sprix Admin 执行记录业务编号设计

## 目标

为 Sprix Admin 的 Mock 执行记录增加真实、稳定、可核对的业务展示编号，避免在运营界面直接展示 `demo:business-execution:*` 内部键。每一条执行记录仍对应唯一的一条验收记录。

## 编号规则

- 格式：`EXE-YYYYMMDD-NNNNNN`。
- 日期取执行记录的提交验收日期 `submittedAt`，按上海时区格式化。
- 流水号取 Excel 5.1 业务快照中的全局执行序号，固定为六位并左侧补零。
- 示例：内部执行键 `demo:business-execution:15452` 对应业务编号 `EXE-20260906-015452`。
- 同一执行记录在列表、详情、任务执行记录、申诉和结算关联中始终使用同一个业务编号。

## 数据模型

- 保留现有 `executionId` 作为内部 Mock 主键和路由参数，继续用于详情查询、验收操作、申诉关联、结算关联及本地状态补丁。
- 新增可选字段 `executionNo`，专门承载业务展示编号。
- 真实后端记录若未提供 `executionNo`，界面继续原样展示后端 `executionId`。
- 不改变后端 Swagger 契约，不改变真实接口请求参数。

## Mock 数据流

1. `business-metrics.mjs` 根据执行提交日期和全局执行序号生成 `executionNo`。
2. 验收记录、任务详情执行记录、申诉记录和执行结果沿用同一 `executionNo`。
3. 内部查询和写操作仍传递 `executionId`，避免破坏现有 `demo:` 路由识别。
4. Mock 列表搜索同时匹配 `executionNo` 与 `executionId`。

## 界面展示

- 平台验收中心“执行记录 ID”列优先展示 `executionNo`。
- 验收详情、任务执行记录、执行结果详情、申诉详情及关联执行记录列均使用同一展示规则。
- 行点击、详情跳转、审批和驳回继续使用内部 `executionId`。
- 不在界面显示内部 `demo:` 前缀；真实后端 ID 不做格式转换。

## 兼容与边界

- 不修改 16,251 条执行记录总量、任务数量、金额、交付方式或验收状态。
- 不修改 Excel 工作簿。
- 不修改真实后端任务及执行 ID。
- 旧 Mock 数据没有 `executionNo` 时回退显示 `executionId`，避免空值。

## 验证

- 静态检查 16,251 条业务编号全部唯一且符合 `^EXE-\d{8}-\d{6}$`。
- 抽查列表、详情、申诉和执行结果中的同一记录编号一致。
- 验证搜索业务编号能命中对应 Mock 记录。
- 验证详情路由及验收操作仍使用内部 `executionId`。
- 按项目规则不运行测试、构建或 Playwright，除非用户当前回合明确要求。
