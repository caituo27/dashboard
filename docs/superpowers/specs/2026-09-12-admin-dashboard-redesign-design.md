# Sprix 管理后台 Dashboard 重设计

## 目标

重构 `apps/sprix-admin` 的数据概览页，使其同时服务管理层和运营人员，并形成清晰的阅读顺序：平台规模、周期经营结果、经营效率、趋势健康度、业务下钻。

页面保持 Sprix 管理后台现有设计语言：白色页面与面板、轻边框、中等圆角、紧凑间距、深灰文字和克制的 teal 强调色。页面不使用渐变、玻璃拟态、大面积阴影、装饰性图标或同权重指标卡堆叠。

## 页面结构

模块顺序固定为：

1. Dashboard 页面头部和周期筛选
2. 平台规模
3. 经营概览
4. 经营趋势与履约表现
5. 任务供给分析
6. 用户访问与行为
7. 关键行为

桌面端使用适配现有后台内容宽度的 12 列网格。第一屏需完整或基本完整呈现页面头部、平台规模、经营概览和经营趋势顶部。模块使用统一边框、圆角、间距和内边距，避免大面积空白。

## 时间上下文

页面头部显示：

- 标题：`Dashboard`
- 副标题：`平台运营数据总览`
- 数据更新时间：`数据更新至 2026-09-11 23:59:59（北京时间）`
- 快捷周期：近 7 天、近 30 天、最近 4 个完整自然周
- 自定义日期范围
- 完整统计区间：`2026-09-05 00:00:00 至 2026-09-11 23:59:59`

平台规模是截至更新时间的累计数据，不受周期筛选影响。经营概览、经营趋势、履约表现、任务供给分析、用户访问与行为及关键行为均跟随周期筛选。数据按日更新，页面刷新后读取最新快照，不使用自动实时刷新。

## 平台规模

平台规模使用一个 `Surface` 容器，内部五等分展示累计指标，不拆成五张独立大卡。标题和截止时间直接标明累计口径，不展示环比或趋势箭头。

## 经营概览

经营概览是第一屏的视觉中心，显示当前统计周期，并分为北极星指标、核心经营指标和辅助指标三个层级。

### 北极星指标

`周验收 GMV` 使用更大的数字、teal 描边和小型北极星标签，不使用渐变。

- 当前值：¥326,840
- 周环比：上升 12.6%
- 上周：¥290,260

点击后进入验收通过订单明细，并携带当前统计周期。

核心指标使用比 GMV 更紧凑的指标块，数字、环比和上周值保持基线对齐。

## 用户访问与行为

用户访问与行为顶部使用紧凑指标块展示 UV 26,824、PV 92,481 和 UV/PV 3.45。下方使用双折线图展示 UV 与 PV 趋势。页面不再保留单独的 PV、UV 大卡，以避免重复。

点击 UV、PV 或趋势数据点打开对应流量明细，并携带指标和日期范围。

## 数据模型与 Mock

扩展集中式 Dashboard snapshot，避免把 Mock 常量散落在 JSX：

- `overview` 保留累计规模数据。
- 新增 `businessOverview`，包含北极星、核心及辅助指标当前值、上期值和变化率。
- 新增 `businessTrends`，按指标保存周期序列。
- 新增 `fulfillment`，保存综合履约率、分项比率和 step funnel。
- `operations.publishedTaskCategories` 保存类别数量与比例所需数据。
- 用户行为序列同时提供 UV 和 PV，按钮事件增加业务行为名称、用户数、次数和转化率。

Mock 数据集中放在 `apps/sprix-admin/mock`，服务层类型只声明契约，React 组件不包含业务 Mock 常量。日期筛选继续由 Dashboard Mock API 处理，7 天、30 天、4 个完整自然周和自定义范围都返回与区间一致的数据。

## 组件边界

- `AdminDashboard`：请求数据、管理统计周期、组织页面顺序和导航下钻。
- `DashboardOverview`：平台累计规模条。
- `DashboardBusinessOverview`：北极星、核心和辅助指标层级。
- `DashboardBusinessTrend`：指标切换、柱状趋势和数据点下钻。
- `DashboardFulfillment`：履约率拆解和紧凑 step funnel。
- `DashboardSupplyAnalysis`：类别横向条形图与发布趋势。
- `DashboardAnalytics`：UV/PV 趋势与关键行为。
- `AnalyticsDetails`：复用现有明细抽屉，并扩展需要的 selection 类型。

组件只接收已计算数据和回调，不自行拼装 Mock 或读取路由。

## 状态与错误处理

- 初次加载继续使用当前 Skeleton。
- 请求失败继续显示错误 Alert 和重试按钮。
- 单个序列为空时在对应面板展示紧凑 Empty，不隐藏整个 Dashboard。
- 数值分母为零时比率显示 `—`，避免 `NaN` 或无限值。
- 下降值使用低饱和红色，上升值使用 teal；比率百分点变化使用 `pp`。

## 响应式

- 1440px 桌面宽度下第一屏突出平台规模与经营概览，保持高信息密度。
- 中等宽度下经营趋势与履约表现改为上下排列，累计规模允许换成 3+2。
- 小屏下指标块单列或双列，图表保持可读，密集表格允许横向滚动。

## 实现范围

本次允许调整 Dashboard React 组件、Dashboard 样式、Dashboard 服务类型、集中 Mock 数据及现有下钻选择逻辑。不得修改 API base、认证、基础路由、部署配置或构建配置。资金结算区域不在本次 Dashboard 中恢复。

## 验收

- 用户能立即区分累计数据和周期数据。
- 第一视觉中心是周验收 GMV，UV、PV 和 Agent 数量不会抢占主层级。
- 指定 Mock 数值与本规格一致。
- 同一语义指标不在页面中以相同层级重复展示。
- 所有有业务意义的指标、类别、漏斗环节、图表数据点和关键行为均可下钻。
- 1440px 下无明显大面积留白，卡片高度、数字基线、标题、图表边缘、网格和内边距统一。
- 页面不自动实时刷新，不展示执行中订单等实时过程状态。
