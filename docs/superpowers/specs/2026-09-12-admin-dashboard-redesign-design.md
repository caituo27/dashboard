# Sprix 管理后台 Dashboard 重设计

## 目标与业务流程

重构 `apps/sprix-admin` 的数据概览页，使其同时服务管理层和运营人员，并形成清晰的阅读顺序：平台规模、周期经营结果、任务运营、经营效率、趋势健康度和业务下钻。

Dashboard 必须忠实表达实际任务生命周期：

`平台发布任务 → Agent 自主选择并接单 → Agent 执行任务 → 任务完成 → 验收 → 验收通过后形成有效成交`

平台不会主动为任务分配执行方，发布任务是平台行为。页面、数据类型、Mock、组件名称、下钻条件和辅助文案均不得引入与实际流程不符的概念。

## 视觉与布局

页面保持 Sprix 管理后台现有设计语言：白色页面与面板、浅灰页面底色、轻边框、中等圆角、紧凑间距、深灰文字和克制的 teal 强调色。正向变化使用 teal 或绿色，负向变化使用低饱和红色。

页面不使用渐变、玻璃拟态、大面积阴影、发光、装饰性图标、大漏斗或大量同权重 KPI 卡片。桌面端使用适配现有后台内容宽度的 12 列网格，第一屏应看到平台规模、经营结果和任务运营，避免大面积留白。

模块顺序固定为：

1. Dashboard 页面头部和周期筛选
2. 平台规模
3. 经营结果
4. 任务运营与任务运营效率
5. 经营趋势
6. Agent 生态
7. 任务供给分析
8. 用户访问与行为
9. 关键行为排行

## 时间上下文

页面头部显示：

- 标题：`Dashboard`
- 副标题：`平台运营数据总览`
- 数据更新时间：`数据更新至 2026-09-11 23:59:59（北京时间）`
- 快捷周期：近 7 天、近 30 天、最近 4 个完整自然周
- 自定义日期范围
- 完整统计区间：`2026-09-05 00:00:00 至 2026-09-11 23:59:59`

平台规模是截至更新时间的累计数据，不受周期筛选影响。其余模块均跟随周期筛选。数据按日更新，页面刷新后读取最新快照，不自动实时刷新。

## 数据模型与 Mock

扩展集中式 Dashboard snapshot，React 组件中不得散落业务 Mock 常量：

- `overview` 保存累计平台规模，不受筛选范围影响。
- `businessResults` 保存周验收 GMV、单均任务价值、验收通过任务数及 Agent 轻量指标。
- `taskOperations` 保存生命周期节点和接单率、完成率、验收通过率。
- `businessTrends` 按指标保存经营趋势序列。
- `agentEcosystem` 保存 Agent 指标和活跃、接单 Agent 趋势。
- `operations.publishedTaskCategories` 保存任务类别数量。
- 用户行为序列同时提供 UV 和 PV。
- 行为排行保存行为名称、用户数、次数和转化率。

Mock 数据集中放在 `apps/sprix-admin/mock`。日期筛选由 Dashboard Mock API 处理，近 7 天、近 30 天、最近 4 个完整自然周和自定义范围均返回与区间一致的数据。

## 组件边界

- `AdminDashboard`：请求数据、管理统计周期、组织模块顺序和导航下钻。
- `DashboardOverview`：平台累计规模条。
- `DashboardBusinessResults`：经营结果和轻量 Agent 运营指标。
- `DashboardTaskOperations`：任务生命周期和任务运营效率。
- `DashboardBusinessTrend`：指标切换、柱状趋势和数据点下钻。
- `DashboardAgentEcosystem`：Agent 指标及趋势。
- `DashboardSupplyAnalysis`：任务类别与发布趋势 Tab。
- `DashboardAnalytics`：UV/PV 趋势和关键行为排行。
- `AnalyticsDetails`：复用现有明细抽屉，并扩展必要的 selection 类型。

组件只接收数据和回调，不自行生成业务 Mock 或读取路由。

## 状态、边界与响应式

- 初次加载继续使用当前 Skeleton，请求失败继续显示错误 Alert 和重试按钮。
- 单个序列为空时在对应面板展示紧凑 Empty，不隐藏整页。
- 分母为零时比率显示 `—`，避免 `NaN` 或无限值。
- 1440px 桌面宽度下第一屏展示平台规模、经营结果和任务运营。
- 中等宽度下左右分析模块改为上下排列，累计规模允许换成 3+2。
- 小屏下指标块单列或双列，图表保持可读，表格允许横向滚动。

## 实现范围

本次允许调整 Dashboard React 组件、Dashboard 样式、Dashboard 服务类型、集中 Mock 数据及现有下钻选择逻辑。不得修改 API base、认证、基础路由、部署配置或构建配置。资金结算区域不在本次 Dashboard 中恢复。

## 验收

- 第一视觉中心是周验收 GMV。
- 用户可明确区分累计数据和周期数据。
- 页面准确表达平台发布、Agent 接单、执行完成和验收通过的任务生命周期。
- 不出现与实际业务不符的流程术语，也不使用传统大漏斗。
- Agent 生态独立展示，UV/PV 不重复堆叠。
- 所有有业务意义的指标、类别、生命周期节点、图表数据点和关键行为均可下钻。
- 1440px 下页面紧凑但不拥挤，卡片高度、数字基线、标题、图表边缘、网格和内边距统一。
- 数据按日更新，页面不自动实时刷新，不展示执行中订单等实时过程状态。
