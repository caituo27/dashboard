# 本地联调与验收约定

最后更新：2026-07-03

## 本地端口

- C 端用户站点默认端口：`5173`
- 管理后台默认端口：`5174`
- 本地后端默认端口：`8084`
- Local Agent 本机服务端口：`8765`

本项目 C 端本地联调以 `http://127.0.0.1:5173/` 为准，不使用临时端口作为默认验收地址。

## 本地后端代理

C 端开发服务需要通过 `/sprix-api` 代理到后端。联调本地后端时，启动前端时应显式指定：

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:8084 pnpm exec vite --host 127.0.0.1 --port 5173
```

Local Agent 绑定回跳也应指向 `5173`：

```bash
--sprix.local-agent.claim-url=http://127.0.0.1:5173/local-agent/claim
--sprix.local-agent.claim-success-url=http://127.0.0.1:5173
```

## 验收边界

Codex 可以通过命令行、接口请求、编译和类型检查验证代码改动，但不要替用户刷新浏览器页面做最终运行态确认。

涉及浏览器页面最终观感、登录态、弹框状态、用户手动操作后的结果时，由用户自己在浏览器中确认。Codex 如需说明验证状态，应明确区分：

- 已验证：接口、编译、类型检查、端口、进程、服务健康检查。
- 待用户确认：浏览器页面刷新后的实际观感和交互结果。

## 线上后端 + 本地前端 + Local Agent 联调

当本地前端需要继续使用线上后端时，可以保持后端不启动，只启动前端并把 API 代理到线上后端。默认前端请求会走 `/sprix-api`，因此需要确认本地开发服务的代理目标指向线上：

```bash
VITE_API_PROXY_TARGET=https://sprix.seeking.work pnpm exec vite --host 127.0.0.1 --port 5173
```

如使用环境变量直接指定 API，也应指向线上 API 前缀：

```bash
VITE_API_BASE_URL=https://sprix.seeking.work/sprix-api pnpm exec vite --host 127.0.0.1 --port 5173
```

### 账号注销接口

C 端前端使用的登录 token 请求头是 `token`，不是 `Authorization: Bearer`。用 token 调账号接口时应这样写：

```bash
curl -sS "https://sprix.seeking.work/sprix-api/api/v1/account" \
  -H "token: <登录 token>"
```

注销当前登录账号：

```bash
curl -sS -X DELETE "https://sprix.seeking.work/sprix-api/api/v1/account" \
  -H "token: <登录 token>"
```

注销后再查同一 token，如果返回 `UNAUTHENTICATED`，说明 token 已失效，账号注销已生效：

```bash
curl -sS "https://sprix.seeking.work/sprix-api/api/v1/account" \
  -H "token: <登录 token>"
```

### 本地 Agent 状态确认

先确认本机 Local Agent 服务是否在运行：

```bash
curl -sS http://127.0.0.1:8765/health
```

返回 `{"status":"ok"}` 表示本地服务存在，不代表当前网页登录账号已经绑定了这台 Agent。

确认本机是否能扫描到可用 Agent：

```bash
/usr/local/local-cli-agent/local_agent.py agents list
```

查看 Local Agent 与线上后端的连接状态：

```bash
/usr/local/local-cli-agent/local_agent.py connection status
```

刷新一次心跳：

```bash
/usr/local/local-cli-agent/local_agent.py connection heartbeat
```

### 注销账号后的重新认领

注销账号或重新注册同手机号后，如果页面提示“未检测到本地 Agent”，通常不是本地未安装，而是新账号还没有重新认领这台本地 Agent。此时不要优先重装安装包，应重新生成认领链接。

注意：网页登录成功只代表当前页面有账号登录态，不代表这台本地 Agent 已经绑定到该账号。账号注销后重新登录线上页面，仍然需要再走一次 Local Agent 认领流程。

如果同时使用线上页面和本地前端页面调试，也要注意二者是不同 origin：`https://sprix.seeking.work` 的登录态不会自动同步到 `http://127.0.0.1:5173`。在哪个页面测试，就需要确保哪个页面本身已有登录态。

生成线上后端认领链接时，需要显式指定 Local Agent Server 地址，避免命中前端域名或错误代理：

```bash
LOCAL_CLI_AGENT_SERVER_URL=http://42.194.150.73:8084 \
  /usr/local/local-cli-agent/local_agent.py connection bootstrap
```

命令会返回 `claimUrl`。在当前浏览器登录态下打开该链接，完成本机 Agent 与当前账号的重新绑定。

轮询认领状态：

```bash
/usr/local/local-cli-agent/local_agent.py connection claim-status
```

看到 `claimed: true` 且 `saved: true` 后，说明本地已保存新账号对应的设备凭据。

最后刷新链路状态：

```bash
/usr/local/local-cli-agent/local_agent.py connection heartbeat
/usr/local/local-cli-agent/local_agent.py connection flush
/usr/local/local-cli-agent/local_agent.py connection status
```

如果 `connection status` 中 `paired: true`、`reclaimRequired: false`、`accessTokenRefreshRequired: false`，说明本机 Agent 与线上后端连接正常。浏览器刷新后，应能在当前账号下继续选择或使用 Agent。
