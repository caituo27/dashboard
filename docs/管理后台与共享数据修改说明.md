# 管理后台与共享数据修改说明

日期：2026 年 9 月 12 日

分支：`feat/admin-dashboard-shared-mock`

对照：本地 `main` 分支

## 1. 这次改动是为了什么

在保留真实任务和原有业务流程的基础上，为管理后台补充数据概览和可操作的展示数据。任务、执行、验收、申诉、结算尽量使用同一套关联记录，避免不同页面只有数量、没有对应明细。

**这是一套真实数据与 Mock 数据混合的展示系统。Mock 不会让真实 Agent 执行任务，也不会产生真实收款或出款。**

## 2. 整个分支新增和调整了什么

| 模块 | 调整内容 |
| --- | --- |
| 数据概览 | 新增入口，展示订单、任务、Agent、趋势、资金和用户行为；支持点击查看明细 |
| 任务管理 | 合并真实与 Mock 任务，支持分页、搜索、查看详情及原有管理操作 |
| 平台验收 | 合并执行记录，保留审核通过、不通过操作；新执行和状态变化会随查询更新 |
| 申诉中心 | 合并申诉记录，按当前页补齐真实详情，减少首次加载请求 |
| 资金管理 | 保留只读结算展示；概览资金指标可打开对应的分页明细，没有新增手动打款入口 |
| C 端本地页面 | 同步可接任务、详情和模拟接单；已下线或没有名额的任务不出现在可接列表中 |
| 页面展示 | 表格超长文字省略，悬浮查看完整展示值；统一分页和自然高度，恢复绿色统计图标 |
| 加载 | 增加共享缓存和增量计算，Mock 明细按页返回，通常每页 20 条 |
| 部署 | 增加管理端静态页面与 Node Mock 服务的联合打包和部署说明 |

## 3. 本次提交重点修改

### 手机号只做展示脱敏

真实手机号保留后端原始值，页面显示为 `138****5678`。验收、执行、申诉、资金列表及详情统一处理，悬浮提示也不会显示被遮住的四位数字。

搜索和接口参数没有替换为虚构号码。Mock 手机号仍按用户 ID 稳定生成，不随刷新变化。

### 沿用原来的业务文案

资金字段统一使用原来的“实际入账”，不再另起“净入账”“已结算净额”的叫法。对应说明和弹窗同步调整，“未提现净额”改为“未提现金额”。

现有审核确认和成功提示已对照 main 保留原文；展示文案调整没有改变真实审核或支付调用。

### 任务状态参考后端规则

依据后端 `SprixServer` 的 main 提交 `31beb5b`：

- 接完最后一个名额，任务自动下线，后台仍保留历史记录。
- 只有已发布任务可以下线，下线需要填写原因。
- 只有已下线任务可以重新发布。
- 名额为零，或下线原因为名额已满的任务，不能重新发布。
- 重新发布后更新发布时间。

这些规则作用于 Mock 数据。真实任务继续使用原后端处理。

### 结算价格与金额精度参考后端

结算采用**创建结算时的任务奖励**，不再固定使用接单时奖励。

例如：接单时奖励 5 元，验收通过前改为 6 元，则新结算按 6 元计算；结算完成后再改为 8 元，已有结算仍保持 6 元。

Mock 通过价格历史重建结算时的价格。历史记录如果缺少完整改价日志，仍无法完整还原所有旧价格。

服务费按奖励的 10% 计算，实际入账按奖励减服务费计算，两项分别四舍五入到分。结算明细、资金汇总和自动打款共用金额算法。

**后端精度规则有一个边界情况：**奖励 1.05 元，服务费原值 0.105 元、实际入账原值 0.945 元，分别保留两位小数后是 0.11 元和 0.95 元，合计比奖励多 0.01 元。Mock 按后端存储口径保留这一结果，不再通过向下取整强行对平。

以上依据是后端源码、数据库字段精度及支付客户端的取整方式，不代表已验证线上实际出款。已有 Mock 数据重新计算后，部分金额可能变化，真实后端记录不受影响。

## 4. 数据概览的数据从哪里来

| 指标 | 来源 |
| --- | --- |
| 任务、订单、执行状态、验收和申诉 | 真实记录与 Mock 记录分别统计后合并 |
| 订单奖励、服务费、实际入账、累计已提现 | 真实资金记录加 Mock 关联记录汇总 |
| 任务发布趋势和最新任务 | 两套任务按发布时间合并 |
| Agent 数量 | 独立的 Mock 增长曲线，尚未接真实 Agent 总数 |
| 试运营天数 | 从 2026 年 7 月 29 日中午起计算 |
| PV、UV、点击、漏斗和用户画像 | 生成的事件与设备地域信息，尚未接入真实采集 |

170 万订单和 3 万 Agent 是 2026 年 9 月 12 日中午的生成基准。订单还会加上真实数量，因此最终页面总数不是强制保持 170 万。

## 5. Mock 数据如何变化

- 根据固定开始时间和当前时间推导数量，服务端按 10 秒生成快照；Dashboard 每 5 秒查询。
- 订单数量按增长曲线变化，包含固定的日、10 分钟和 30 分钟周期波动。
- 任务由基础执行订单分组得到，并提前约 100～140 分钟发布。
- 执行按类别安排时长，到时间后进入提交和验收阶段。C 端手动接取的 Mock 任务到时间进入待平台验收，后续由管理端处理。
- Agent 总量采用另一条增长曲线，不等于真实注册或在线数量。
- 同一个 ID 的名称、用户和基础时间线保持稳定。管理员操作单独保存，服务重启后保留。
- 即使没有用户访问，基础生成数量也会继续随时间变化。

## 6. 真实流程和 Mock 流程如何区分

真实 ID 继续调用真实后端；Mock ID 调用独立 HTTP 服务，操作状态保存在独立文件中。页面隐藏内部 Mock 标识，但两套数据没有写入同一个真实数据库。

真实 C 端接单、真实验收和自动打款流程不变。Mock 接单能在后台看到对应执行；完成后生成结算和自动打款记录，但不会增加真实钱包余额。

## 7. 尚未完成的部分

| 项目 | 当前限制 |
| --- | --- |
| 实际执行与交付 | Mock 按时间推进，没有真实调用 Agent，也没有生成配套交付文件 |
| 自动打款 | Mock 完成即成功，未完整模拟支付处理中、失败和账户异常 |
| 行为分析 | 不是实际点击上报，真实接单不会自动增加这套生成事件的点击数 |
| Agent 总量 | 曲线增长尚未全部对应到新增 Agent 实体记录 |
| 基础任务历史 | 尚未完整重放历史上架、下架与每次接单校验 |
| 分页 | Mock 已按页返回，部分真实接口仍全量读取后整理 |
| 刷新按钮 | 自动查询仍会让刷新按钮转圈，已定位，尚未修改 |
| 生产 C 端 | 共享 Mock 当前只在开发环境启用，不能只部署管理端就认为生产 C 端也已同步 |
| 部署保护 | Mock 服务没有服务端身份校验；前端登录不能保护直接调用，需按部署说明配置访问保护 |

页面订单金额不等于平台实际收入；平台服务费也不等于扣除成本后的利润。

## 8. 验证与提交边界

开发过程中已执行手机号脱敏、任务状态、C 端模拟接单、结算价格、金额精度、资金增量一致性等针对性检查。结算价格变更后的相关失败用例已修正并复测通过。

本次提交前检查代码差异，不额外重跑全量测试、构建或真实支付流程。后端仓库、真实数据库和线上配置未修改；本次只做本地提交，不推送远程。
