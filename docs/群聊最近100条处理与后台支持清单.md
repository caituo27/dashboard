## 需要后台支持或继续确认

| 阻塞点 | 需要后台提供/确认 | 前端当前策略 |
| --- | --- | --- |
| 人脸核验完成确认 | Swagger 中 `POST /api/v1/account/qualification/real-person-complete` 仍没有明确 `certifyId` 参数。需要后端确认该接口必须按本次 `certifyId` 校验，或新增 `GET /face-verification/{certifyId}/status` 状态查询接口 | 前端已把 `certifyId` 作为 query param 传入；若后端忽略该参数，仍可能误读旧认证状态 |
| 支付宝绑定收款账户无成功反馈 | 需要绑定会话轮询接口返回稳定终态，并在完成后返回或立即写入 `withdrawalAccount`。同时需要确认支付宝 IP/域名风控提示的正式域名配置 | 前端已兼容多个成功状态，并在成功后补查当前提现账户 |
| 接单失败 `Current execution agent is not available` | 需要后端/LocalCLIAgent 返回更清晰的在线新鲜度、WebSocket、lastSeen、pendingCommand 状态；LocalCLIAgent 断线重连和 heartbeat 要能让服务端恢复 ready device | 前端不硬改“已连接”等于可接单；真实可接单仍以后端 ready device 为准 |
| Agent 评测 3-6 步动效不明显/一直卡住 | 需要后端返回稳定的六步进度或最终状态，不只返回 running/空步骤 | 前端只修初始步数展示，不伪造真实后端进度 |
| 管理端执行详情/用户信息/Agent 信息按钮 | 需要后台提供执行详情、用户详情、Agent 详情、结果文件、验收报告、结算详情等接口或详情字段 | 前端保留按钮文案，但无真实目标的动作仍禁用并说明待接口 |
| 操作日志完整性 | 需要后端在创建、编辑、下线、重新发布、删除、审核通过/不通过、资金操作等节点持续写操作日志，并统一返回操作人字段 | 前端已兼容常见字段并映射中文；没有返回的操作不会凭空补 |
| 接单资格记录字段 | 需要返回认证主体脱敏、认证时间、协议版本、签署时间、正式协议内容/版本 | 前端只展示已有状态和待后端返回占位 |
| C 端结算明细/历史提现/打款进度 | 需要 C 端结算明细、历史提现申请、提现审核/打款进度刷新接口 | 前端不伪造历史记录，只展示本次请求返回和待接口空态 |
| 设计类反馈“icon 太丑/列表样式需要调整/文案要改一下” | 需要产品或设计标注具体页面、组件和目标样式；当前聊天截图无法唯一定位所有改动 | 前端已处理能定位的按钮和中文文案，剩余不猜 |

## 联调建议

1. 先用新账号完成一次人脸核验，确认 `certifyId` 和认证结果是一一对应，不会复用旧账号状态。
2. 再走支付宝绑定收款账户，确认绑定会话轮询能返回终态，且 `/account/withdrawal-account` 随后能读到新账户。
3. 用一个执行中任务调用终止接口，确认服务端记录变为 `TERMINATED`，LocalCLIAgent 也能收到并上报终止。
4. 管理端打开任务详情，确认执行节点、操作日志、操作人和申诉标签都使用真实字段展示。
