# Sprix 滚动与固定布局规范

## 目标

Sprix 页面遵循一个原则：同一屏内只保留一个主要纵向滚动容器。普通内容卡片不做内部纵向滚动，避免用户同时面对页面滚动、卡片滚动和弹框滚动。

## 页面滚动类型

### 整页自然滚动

适用场景：

- 官网首页、介绍页、协议页、登录页、授权回调页。
- 内容以阅读和引导为主，用户按顺序浏览。
- 类似 Apple 官网的营销页面：模块跟随页面自然滚动，顶部区域不强行制造工作台式固定布局。

设计规则：

- 使用页面自身滚动，不在正文卡片里增加纵向滚动条。
- 页面高度使用 `100dvh`，避免移动端浏览器地址栏变化造成视觉跳动。
- 头部、主标题、说明文案跟随页面滚动，除非存在跨页面常驻导航。

### 应用壳内主内容滚动

适用场景：

- C 端登录后的任务市场、任务详情、Agent 中心、资金记录等工作台页面。
- 管理端任务审核、用户管理、结算、配置等高频操作页面。

设计规则：

- `.sprix-shell` 固定在一屏内，侧边栏保持可见。
- `.sprix-main` 是唯一主要纵向滚动容器。
- 内容区内部的普通卡片、描述块、统计块不再单独纵向滚动。
- 移动端回到整页自然滚动，侧边栏不再固定，减少小屏多滚动区。

## 滚动模式决策树

新增页面或改版页面时，按以下顺序判断：

1. 这个页面是否以阅读、引导、授权、登录或营销展示为主？
   - 是：使用整页自然滚动。
   - 否：继续下一步。
2. 这个页面是否属于登录后的工作台，用户需要反复切换页面、查看状态或执行操作？
   - 是：桌面端使用应用壳内主内容滚动。
   - 否：继续下一步。
3. 这个页面是否只有一个短流程或一次性确认动作？
   - 是：优先整页自然滚动，必要时用普通页面居中布局。
   - 否：继续下一步。
4. 内容是否是表格、日志、代码、弹框正文这类天然长内容？
   - 表格：只允许横向滚动，纵向交给 `.sprix-main`。
   - 日志/代码：允许局部滚动，但必须放在折叠区或证据块中。
   - 弹框正文：允许弹框 body 滚动。
   - 普通描述和详情正文：不允许局部纵向滚动，使用自然换行。

一句话判断：用户是在“读一段页面”，就整页滚动；用户是在“操作一个后台或任务台”，就应用壳滚动；用户是在“查看一段长证据”，才允许组件内部滚动。

## 固定区域规则

### C 端

- 首页、Agent 中心、任务详情标题区默认跟随主内容滚动。
- 任务详情里的主要操作按钮可以放在内容顶部或状态区，不做全局 sticky，避免遮挡阅读内容。
- 原始执行日志可以局部滚动，因为它属于长文本证据，不是主阅读流。

### 管理端

- 页面头部和主操作区可以 sticky，适合审核、筛选、表格处理等反复操作场景。
- 表格横向溢出优先使用表格自身横向滚动。
- 表格外层不再额外套纵向滚动容器，纵向滚动交给 `.sprix-main`。

## 组件内部滚动白名单

仅以下组件允许内部滚动：

- 弹框、抽屉的 body。
- 原始日志、代码、stderr/stdout 等长文本证据块。
- 表格横向滚动区域。
- 下拉选择、菜单、日期选择器等 Ant Design 标准浮层。

不允许内部纵向滚动：

- 普通信息卡片。
- 任务要求、Agent 输出、历史执行、能力画像正文。
- 管理端筛选区、统计区、详情摘要区。

## 实现约定

- 桌面端应用壳：`.sprix-shell { height: 100dvh; overflow: hidden; }`。
- 桌面端主内容：`.sprix-main { overflow-y: auto; min-height: 0; }`。
- 移动端：`.sprix-shell` 使用 `min-height: 100dvh`，`.sprix-shell` 和 `.sprix-main` 恢复 `overflow: visible`。
- 弹框高度使用 `dvh`，例如 `max-height: min(82dvh, 760px)`。
- 不新增自定义滚动条样式，除非是日志或弹框内部的低干扰滚动条。

## 验证边界

- 静态搜索应只允许以下纵向滚动：`.sprix-main`、弹框 body、日志/代码证据块。
- 静态搜索应允许管理端表格横向滚动：`scroll={{ x: ... }}`。
- `100vh` 只允许作为 `height: 100dvh` 的兼容 fallback，页面级高度应使用 `100dvh`。
- 最终视觉验收需要在真实浏览器中检查桌面端和移动端视口；仅 build/typecheck 不能证明视觉完成。

## 提交前静态核查命令

在 `SprixPortal` 根目录执行：

```bash
rg "overflow-y: auto|overflow: auto|max-height|position: sticky|scroll=|overflowY" -n apps/sprix-agent/src apps/sprix-admin/src --glob '!**/apis/**'
rg "100vh|min-h-screen|h-screen|calc\(100vh" -n apps/sprix-agent/src apps/sprix-admin/src --glob '!**/apis/**'
pnpm typecheck
pnpm build
```

判定方式：

- 第一条命令中，纵向滚动只能出现在 `.sprix-main`、弹框 body、日志/代码证据块；管理端 `Table` 的 `scroll={{ x: ... }}` 属于横向滚动白名单。
- 第二条命令中，`100vh` 只应出现在 app shell 的 `height: 100dvh; min-height: 100vh;` fallback 里。
- `pnpm typecheck` 和 `pnpm build` 必须通过；build 的 chunk size warning 不属于滚动布局问题。

## 人工视觉验收路径

桌面端建议检查 1440px 宽度，移动端建议检查 390px 宽度。

C 端：

- `/`：首页应为整页自然滚动，不出现应用壳侧边栏。
- `/auth/callback/:provider`、`/local-agent/claim`：独立页应居中展示，使用整页自然滚动。
- `/agent/market`、`/agent/center`、`/agent/my-tasks`、`/agent/earnings`、`/agent/qualification`：桌面端只有 `.sprix-main` 纵向滚动，侧边栏保持可见；移动端回到整页自然滚动。
- `/agent/task/:id`：公开任务详情的说明、交付标准、验收标准应自然换行，不出现卡片内纵向滚动。
- `/agent/my-tasks/:id`：任务要求、Agent 输出、验收结果、历史执行应跟随主内容滚动；只有日志/事件详情展开后允许局部滚动。

管理端：

- `/login`：独立登录页整页居中，不使用后台应用壳滚动。
- `/tasks`、`/acceptance`、`/appeals`、`/funds/*`：桌面端只有 `.sprix-main` 纵向滚动，表格只允许横向滚动。
- `/tasks/:id`、`/acceptance/:executionId`、`/appeals/:id`：详情长文本自然换行，不出现普通详情卡片内纵向滚动。
- 管理端页面头部在桌面端 sticky，移动端恢复普通文档流。

## 自查清单

- 当前视图是否只有一个主要纵向滚动容器？
- 普通卡片有没有因为 `max-height + overflow` 产生内部滚动？
- 固定区域是否真的服务于高频操作，而不是只是看起来稳定？
- 移动端是否回到自然页面滚动？
- 长日志、代码、表格是否使用了明确的局部滚动白名单？
